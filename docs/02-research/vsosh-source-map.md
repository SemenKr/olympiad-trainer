# ВсОШ Mathematics — Source Map

## Цель

Определить надёжные источники реальных олимпиадных задач и правил, на которых будет строиться первая версия Olympiad Trainer.

Фокус MVP:

* математика;
* 5 класс;
* подготовка к ВсОШ.

## Приоритет источников

### 1. Официальный портал ВсОШ

https://vserosolimp.edsoo.ru/matematika

Использовать как основной источник для:

* методических рекомендаций;
* структуры этапов;
* официальных требований;
* критериев и методик оценивания;
* проверки изменений между учебными годами.

Актуальная базовая версия требований для исследования:
`2026/27 учебный год`.

### 2. Сириус — школьный этап ВсОШ

https://siriusolymp.ru/2025/mathematics

Полезен для:

* реальных заданий школьного этапа;
* текстовых разборов;
* правил конкретного тура;
* анализа форматов задач.

Для 5 класса в 2025:

* время: 60 минут;
* максимальный результат: 56 баллов;
* дополнительные материалы не предусмотрены.

На странице представлены несколько групп вариантов. При дальнейшем аудите не считать один вариант репрезентативным для всего этапа.

### 3. Сириус — пригласительный этап

https://siriusolymp.ru/invite2026/mathematics

Использовать как дополнительный источник задач для обучения и анализа progression.

Для 5 класса в 2026:

* время: 90 минут;
* дополнительные материалы не предусмотрены;
* доступен текстовый разбор.

### 4. Московский официальный архив ВсОШ — vos.olimpiada.ru

[ВсОШ в Москве — портал Центра педагогического мастерства](https://vos.olimpiada.ru/)

Использовать как официальный московский архив заданий и решений с привязкой к году, этапу, классу и варианту. В OT-001B изучены [школьные задания 2025/26 для 5 класса](https://vos.olimpiada.ru/upload/files/Arhive_tasks/2025-26/school/math/tasks-math-5-sch-msk-25-26.pdf), [пригласительные задания 2025](https://vos.olimpiada.ru/upload/files/Arhive_tasks/2025-26/prigl/math/tasks-math-5-prigl-msk-25-26.pdf) и [пригласительный разбор](https://vos.olimpiada.ru/upload/files/Arhive_tasks/2025-26/prigl/math/sol-math-5-prigl-msk-25-26.pdf).

Research finding: правила и формат тура нельзя предполагать одинаковыми для всех регионов/платформ только по ключу `olympiad + year + stage + grade`. Московский школьный PDF указывает максимум 8 баллов, по 1 баллу за задачу без частичных баллов; описание Сириуса выше для 5 класса в 2025 указывает максимум 56. Значения относятся к конкретным источникам и не переносятся на другой регион/платформу. Архив публикации сам по себе не устанавливает платформу проведения.

При исследовании сохранять регион/платформу (если подтверждены), provenance варианта и ссылку на правила конкретного тура. Это исследовательское требование, не DB-решение. Подробности: [OT-001B — Problem Content Audit](problem-content-audit.md).

## Source policy

При анализе каждой задачи фиксировать:

* source;
* academicYear;
* olympiad;
* stage;
* grade;
* variant/group, если известен;
* problemNumber;
* originalUrl;
* наличие официального решения/разбора.

Не считать собственной классификацией источника:

* topic;
* skill;
* method;
* difficulty.

Эти поля будут результатом нашего анализа, а не официальными metadata.

## Контентные правила проекта

На этапе исследования:

* не делать массовый scraping;
* не импортировать архив целиком;
* не предполагать наличие публичного API;
* не изменять оригинальные условия при анализе;
* всегда сохранять provenance задачи;
* сторонние источники не использовать как замену официальному источнику, если оригинал доступен.

Перед публичной публикацией набора задач отдельно провести проверку условий использования/авторских прав.

## План выборки для первого аудита

Первая выборка: примерно 10 задач.

Ориентир:

* 6 задач школьного этапа ВсОШ;
* 4 задачи пригласительного этапа;
* все для 5 класса;
* выбирать задачи разных типов, а не только первые по порядку.

Цель выборки — обнаружить необходимые свойства модели Problem, а не оценить ученика.

## Следующий шаг

`OT-001B — Problem Content Audit`

Для каждой выбранной задачи определить:

* что требуется от ученика;
* формат ответа;
* математическую область;
* конкретный навык;
* метод/идею решения;
* требуемое обоснование;
* возможные ступени подсказок;
* какие данные должна уметь хранить будущая модель Problem.

Не создавать data model до завершения аудита.
