# Adaptive Practice v0 — two explicit transfer paths

The fixed three-problem core remains unchanged. A separate `transfer` Practice episode contains exactly one of `brothers-ages-products` (G5S-1) or `parrots-guaranteed-colors` (task 5.6), using the existing answer, hint, solution, checkpoint, pause, Summary and immutable Finish transitions. This is an explicit mode, not a general planner or fourth unconditional core item. Existing core snapshots and completed summaries remain readable.

Home first offers Resume for any unfinished episode. Otherwise it reads verified PostgreSQL evidence after legacy import. It evaluates I-08 → G5S-1 first: the latest positive I-08 checkpoint fact must have no later I-08 incorrect fact, and G5S-1 must never have been attempted or solution-exposed. Only if that path is ineligible, it evaluates sock → parrots by the same rule using a verified positive sock checkpoint and parrots status. If both paths qualify, G5S-1 wins. A later source incorrect suppresses the current recommendation until a new verified source correct. The reason comes from the latest eligible source fact's hint exposure and reveals no transfer strategy. Invalid or unavailable evidence is a retryable read failure, not an absence of recommendation. Direct opening of the transfer route checks the selected problem ID against the same server rule before creating a local episode.

The server returns learner-safe adaptive availability as `recommendation`, `insufficient-evidence`, or `transfer-exhausted`, alongside a separate factual `hasPracticeHistory` boolean. Exhaustion means both explicit transfer targets have been attempted or solution-exposed; an unattempted target without a positive source basis remains insufficient evidence. History comes from verified evidence, durable transfer status, or a Finish receipt, including a Finish with no checkpoint contribution. A verified browser-local completed Summary also makes a learner returning on Home. Home precedence is unfinished episode → recommendation → fresh core Practice → returning insufficient evidence → returning exhausted. The last two states lead to Progress and make no mastery or completion claim.

The paths test recognition of structured arguments in a new setting: global impossibility for I-08 → G5S-1 and guarantee under unfavorable choice for sock → parrots. The UI gets only the problem ID and learner-safe reason; it never receives evidence slots, option IDs, sequences or a score. Transfer checkpoint success can raise only its corresponding capability to bounded recognition groups; main-answer correctness alone cannot. The two capabilities remain independent. Neither recommendation nor derived Progress wording is stored.

The adaptive Finish receipt hashes the same immutable request's exact transfer problem ID, factual checkpoint contribution if any, and attempted/solution-exposed state. A completed attempt without a checkpoint therefore suppresses a repeat recommendation without manufacturing positive evidence. PostgreSQL keeps per-transfer attempted and solution-exposed booleans plus the evolved factual evidence buckets; unfinished Practice and latest Summary remain browser-local. Existing brothers receipts and pending Finish requests remain recoverable.
