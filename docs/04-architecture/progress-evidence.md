# Progress Evidence v0

The checkpoints for `guaranteed-sock-pair` and `table-impossible-sums` have two explicit browser-local factual buckets at `olympiad-trainer:progress-evidence-v0`. The store is separate from the latest completed Practice summary and is updated only when a session with an eligible checkpoint observation finishes durably. The first bucket supports `Как гарантировать результат`; the second supports `Доказывать, что что-то невозможно`.

Each bucket retains three facts: the latest correct checkpoint without earlier hints, the latest correct checkpoint with earlier hints, and the latest incorrect checkpoint. Each contribution receives the next positive sequence number within its bucket; replacing one slot leaves the other two intact. A fact contains only the fixed problem ID, the checkpoint observation, ordered hint levels exposed before submission, and `solutionExposedBeforeCheckpoint: false`. No answer draft, protected prompt or options, interpretation, score, or mastery state is stored. The existing version 1 guarantee-only shape remains readable; the first table contribution migrates it to a version 2 wrapper with both explicit buckets.

Contributing Finish first checks that the saved unfinished snapshot still matches the episode. A Practice-specific pending transition record keeps the prior and intended values while the unfinished, latest-completed, and Progress keys change. It is removed before successful completion is reported. A retry reconciles that record before assigning any new sequence; an unresolved or conflicting transition blocks further completion.

The browser validates the exact snapshot shape and sequence constraints. Before a retained fact affects interpretation, a server action checks every retained option and outcome against the canonical server-only checkpoint checker. Invalid or unverifiable reads do not mutate storage, and `/progress` shows an error rather than an empty state; a failed verification request leaves the stored snapshot available for retry. Interpretation is derived only on verified read. Both groups are capped at `Начинаю разбираться`; repeated structured recognition of either checkpoint does not establish independent proof construction, transfer, reliability, or mastery. Incorrect-only evidence creates no weakness label, and later incorrect evidence does not erase an earlier positive fact.
