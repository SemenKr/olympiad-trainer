# Progress Evidence v0

The checkpoints for `guaranteed-sock-pair`, `table-impossible-sums`, and the explicit transfer problems `brothers-ages-products` and `parrots-guaranteed-colors` have two explicit factual capability buckets. The browser-local `olympiad-trainer:progress-evidence-v0` value is a legacy source imported once into [Server-backed Learner Persistence v1](server-backed-learner-persistence.md). New contributing Finish transactions update PostgreSQL. The guarantee bucket supports `Как гарантировать результат`; the impossibility bucket supports `Доказывать, что что-то невозможно`.

The guarantee bucket keeps separate three-slot sections for sock and parrots, with one deterministic `nextSequence` across both; legacy sock-only v1 remains readable and migrates on the first parrots contribution. The impossibility bucket keeps separate three-slot sections for I-08 and G5S-1, with one deterministic sequence across both; the old I-08-only shape remains readable and migrates on the first G5S-1 contribution. Each section keeps the latest correct checkpoint without earlier hints, the latest correct checkpoint with earlier hints, and the latest incorrect checkpoint. A fact contains only the fixed problem ID, checkpoint observation, ordered hint levels exposed before submission, and `solutionExposedBeforeCheckpoint: false`. When either transfer checkpoint succeeds without hints, its bucket also retains the preceding eligible source fact's sequence, observation and hint exposures: I-08 for G5S-1, sock for parrots. The server captures this basis from verified evidence and rechecks it canonically on read, so later source slot replacement cannot rewrite the transfer interpretation. No answer draft, protected prompt or options, interpretation, score, or mastery state is stored. The guarantee-only top-level shape also remains readable.

The original browser-local Finish used a Practice-specific pending transition record across unfinished, latest-completed and Progress keys. In v1, new contributions are appended to PostgreSQL before local Summary finalization; a local pending record still protects retry and recovery of that finalization.

The server validates exact snapshot shapes and sequence constraints on import and read, and rechecks every retained option and outcome against the canonical server-only checkpoint checker. Invalid or unverifiable reads do not mutate storage, and `/progress` shows an error rather than an empty state; a failed import leaves browser-local bytes available for retry. Interpretation is derived only on verified read. Independent transfer recognition after a supported source checkpoint reaches `Уже получается`; after an independent source checkpoint it reaches `Получается в разных задачах`. Hinted transfer recognition remains `Начинаю разбираться`; incorrect-only evidence creates no weakness label and later incorrect evidence does not erase earlier positive evidence. Conclusions are bounded to recognition of the relevant structured argument, without a claim about proof construction, reliable mastery, method selection or difficulty.

The explicit `pages-without-digit-one` exploration adds a third, separate enumeration bucket for `Систематически перебирать случаи и обосновывать полноту` (`Проверять все возможные случаи`). Its three factual slots retain the latest correct checkpoint without hints, correct checkpoint with hints, and incorrect checkpoint. Each fact contains only problem ID, checkpoint observation, prior hint levels, and `solutionExposedBeforeCheckpoint: false`. PostgreSQL migration starts existing learners with empty enumeration evidence; old browser-local one- and two-bucket values remain readable and import as empty enumeration. The canonical server checker validates the checkpoint outcome. A correct main answer alone, skipped episode, or solution-exposed work adds no positive observation.

One verified correct enumeration checkpoint, with or without hints, yields only `Начинаю разбираться` and a conclusion about recognizing a complete, non-overlapping partition. It does not claim independent construction, transfer, repeated reliability, or mastery. With no positive checkpoint, the group is null and the conclusion is neutral. Guarantee and impossibility evidence and interpretations remain independent.
