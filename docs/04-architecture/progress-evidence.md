# Progress Evidence v0

The checkpoints for `guaranteed-sock-pair`, `table-impossible-sums`, and the explicit transfer problem `brothers-ages-products` have two explicit factual capability buckets. The browser-local `olympiad-trainer:progress-evidence-v0` value is a legacy source imported once into [Server-backed Learner Persistence v1](server-backed-learner-persistence.md). New contributing Finish transactions update PostgreSQL. The first bucket supports `Как гарантировать результат`; the second supports `Доказывать, что что-то невозможно`.

The guarantee bucket retains three slots. The impossibility bucket keeps separate three-slot sections for I-08 and G5S-1, with one deterministic sequence across both; the old I-08-only shape remains readable and migrates on the first G5S-1 contribution. Each section keeps the latest correct checkpoint without earlier hints, the latest correct checkpoint with earlier hints, and the latest incorrect checkpoint. A fact contains only the fixed problem ID, checkpoint observation, ordered hint levels exposed before submission, and `solutionExposedBeforeCheckpoint: false`. When G5S-1 succeeds without hints, the bucket also retains the preceding eligible I-08 fact's sequence, observation and hint exposures. The server captures this basis from verified evidence, and rechecks it canonically on read, so later I-08 slot replacement cannot rewrite the transfer interpretation. No answer draft, protected prompt or options, interpretation, score, or mastery state is stored. The guarantee-only shape also remains readable.

The original browser-local Finish used a Practice-specific pending transition record across unfinished, latest-completed and Progress keys. In v1, new contributions are appended to PostgreSQL before local Summary finalization; a local pending record still protects retry and recovery of that finalization.

The server validates exact snapshot shapes and sequence constraints on import and read, and rechecks every retained option and outcome against the canonical server-only checkpoint checker. Invalid or unverifiable reads do not mutate storage, and `/progress` shows an error rather than an empty state; a failed import leaves browser-local bytes available for retry. Interpretation is derived only on verified read. Guarantee remains capped at `Начинаю разбираться`. For impossibility, independent G5S-1 recognition after supported I-08 recognition reaches `Уже получается`; after independent I-08 recognition it reaches `Получается в разных задачах`. These bounded groups do not claim independent proof construction, reliability, or mastery. Hinted G5S-1 recognition remains `Начинаю разбираться`; incorrect-only evidence creates no weakness label and later incorrect evidence does not erase earlier positive evidence.
