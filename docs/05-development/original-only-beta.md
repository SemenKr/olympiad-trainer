## Access contract

`practice/server/content-access.ts` is the single server authority: the explicit Pack S/T tuples contain six approved IDs. An `original` provenance tag never grants access. Production/default/unknown environments and Vercel deployments enforce this policy, including when `ORIGINAL_ONLY_BETA=false`. Local `NODE_ENV=development` and test workflows retain the full catalog; `ORIGINAL_ONLY_BETA=true` enables beta checks there. There is no Production opt-out setting.

Home starts S; chooser offers only S/T. Approved Practice uses existing Pack sessions with the initial legacy core prerequisite disabled only in this server-selected beta path. Server projections filter before serialization. New answer/hint/solution/checkpoint actions and Finish reject legacy IDs/episodes. Finish still applies the existing canonical facts, ordered prefix, ownership, generation and idempotency validation; beta adds admission restrictions, not alternate validation. Server-only raw definitions remain intact for historical verification.

Transfer, adaptive/review entry, Simulation and knowledge support are temporarily unavailable; guarded routes/actions give no legacy content. Sources lists only approved original attributions, without granting a license or human certification. Content identities, SQL, registered tuples, persistence schema and adopted learning evidence are unchanged.

## Existing state and recovery

Beta Practice and Summary inspect retained work before verification/repair. Legacy sessions, summaries, Finish outboxes and legacy Finish markers are blocked with Russian explanations; they are not rendered, deleted, acknowledged or converted. Approved T conflicts link to the actual saved Pack, rather than the S default. Unknown/corrupted state is never admitted by these preflights.

History keeps authenticated factual titles/outcomes/receipts; no old statements, support or new assessment results are returned. Beta hides legacy recommendation/path/review cards and legacy evidence interpretation. Its progress import path runs under existing locks and performs no local recovery planning or writes. A non-null retained legacy evidence payload is never falsely acknowledged as an empty import. If the server baseline has not been initialized, beta refuses new Finish until the original payload can be imported by a compatible full-catalog build; new beta sessions are conservatively blocked while retained local evidence exists. This deliberate fail-closed restriction preserves the later import path. Existing canonical ownership, Recovery, Start Fresh isolation and database records remain authoritative; beta does not reset an owner or erase data to unblock entry.

This code cannot remove content already present in a frozen tab or make a separate older deployment enforce this policy. A release must retain the maintenance fence until the approved beta artifact is independently tested on the intended protected host, old tabs/deployments/actions are retired under the existing operational runbook, and public opening is separately authorized. A full-catalog build is not an approved public writable rollback for this beta. Use a protocol-compatible, exposure-compatible candidate/roll-forward; preserve pending work.
