## Failure boundaries and approvals

Before resuming any voluntarily paused service after a failed migration, establish whether the original or committed expanded schema is present. Keep capture and flags while old writers remain. The additive bridge supports normal legacy application writes, not arbitrary privileged DDL; freeze known administrative schema changes. After any real learner, Recovery or background write is acknowledged following the snapshot, never restore it over that state. Fix forward or use the protocol-compatible application rollback on the expanded database. Operator-only synthetic smoke does not prove unknown external writers were absent.

Production remains **NO-GO** pending fresh verified recovery evidence, separately approved atomic expansion/readback, limited runtime and rollback readiness, verified guarded deployment/alias sequence, functioning authenticated smoke and separate public-release approval. Provider-assisted NOLOGIN and proof that no external clients exist are not additive-expansion gates. Strict permanent old-writer retirement and 0017 remain separately gated.
